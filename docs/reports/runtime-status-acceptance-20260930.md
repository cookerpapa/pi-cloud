# 运行状态、链路探针与租约扫描验收

日期：2026-09-30。决定：[ADR-0201](../adr/0201-runtime-activity-and-path-probes.md)。
已部署运行版本：`694983ac2405a479ad33959f49ebe4d479e3a4cd`。
Guest 构建内容未变，继续使用 `c4d974ffa0aac9e857876b1ff2668b88c217761c`。

## 实现

控制面分别运行租约过期扫描与远程 Worker 清理，两个循环各自串行、有界，
并独立设置扫描/清理批次上限。远程停止的等待不再阻塞下一次租约扫描。
初筛使用一次 PG 时间取值，最终仍在拿锁后重新确认，覆盖控制面时钟快慢一小时
及续租竞争。默认一秒是扫描完成后的间隔，不承诺一秒内发现任意故障。

每个活跃 Turn 持续显示运行阶段，已有文字后也保留。可信 Runner 根据原生 Pi
事件产生阶段与最近活动时间，HTTP/SSE 只发送 PiCloud 自己的有界字段，
不发送思考内容、部分参数或原生事件对象。工具日志更新也可刷新最近活动。
取消和终态优先；重连先回到未知状态，重新开始观察窗口。

普通执行记录提供链路证据；静默时，每个物理 Session 最多每 15 秒补一条
`path_probe`，与子 Lane 共用。探针走原有 producer、Session 分区和 Projector，
不生成 Pi Entry、PG 历史、显示序号、Tool 命令或模型上下文，也不参与续租。
同一 Session 最多一条探针在途；其 ACK 不成为后续语义写入或收尾的额外等待点。
共享 producer 的真正故障仍沿原有失败处理收敛。

前台分开显示最近活动与链路确认。原始时间和单调位置防止重放刷新健康状态，
45 秒缺少新链路证据时提示延迟。链路通畅不能证明模型或工具取得了进展；
执行权限始终由 PG lease 决定。探针是观测通路进入 Kafka 的明确例外，普通阶段
与 Tool 进度仍使用可丢失的 HTTP/SSE。

保留启动时的基线 HEAD 和 dirty 标记；验证记录另保存实际部署版本与源码摘要。

[真实 Luna/Cube/Chrome 验收](runtime-status-live-20260930.json)：

1. Luna 依次完成 write/read/edit/bash。Bash 写入并 fsync 一行见证文件后静默
   120 秒，前台仍显示工具阶段并收到链路确认。
2. 暂停控制面，前台显示状态更新延迟，PG 查询确认 Worker 租约仍有效。
   随后替换控制面进程，收到新时间戳的链路确认。静默区间原生日志条数不变；
   最终见证文件恰好一行，所观察的命令没有重跑。
3. 取消另一条静默 Bash，Run 取消、状态栏消失，终态之后没有收到迟到观测。
4. 强制停止并重启执行中的 Worker，原 Run 以 `assignment_lost` 失败，状态栏
   结束。新 Run 使用不同 Worker 身份，成功读取原 Workspace 文件。事后 PG
   原生日志核对确认首轮四种文件工具各调用一次，恢复轮的两次 read 均成功，
   返回了预期文件内容；取消和丢失 Worker 的 Bash 均保留错误结果。

正式场景包含两个完成 Run、一个取消 Run、一个 Worker 丢失失败 Run。此前两次
验收尝试分别因统计 SQL 类型和浏览器语言断言中止；已修正脚本，取消各自的 Run
并清除 Workspace。执行时脚本原文保存在提交 `a6d18b30`，报告记录其 SHA-256；
之后只做代码格式整理，不将早期失败尝试计为正式验收成功。

## 部署、清理与边界

Worker、控制面和 Web 已配套部署且健康；没有数据库迁移或 Guest 模板替换。
原有 **1,417 条原生日志**在部署前后及验收结束后校验值一致，最后一次计算排除
本次创建的三个临时租户。三个测试 Workspace 均确认存储已清除，三个测试凭据
均已撤销，隔离测试 PG 已移除。当前无活跃 Run、未释放 Session lease、未投影
seal 或未发布终态。

旧版消费者不能读取新探针，回退需遵守 ADR-0201 的静默与恢复范围要求。
本次是单机部署的真实进程故障验收，不据此声称多机 HA，也不声称任意 shell
副作用恰好执行一次。
