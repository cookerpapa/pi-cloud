## Verification

The provider configuration, translator and management suites pass, as do the
OpenAI-compatible executor suite, focused native/route/diagnostic race checks,
and required server builds. Local PiCloud contracts cover native Pi serialization
across processes, images, continuation, cancellation, fallback, bounded decoding,
configuration conversion and byte-identical management receipts. Reused connections
and fallback attempts retain separate v8 usage execution IDs.

Scoped PiCloud checks passed 71 assertions before the additional operator-fixture
checks; the admission-refinement run passed 33 assertions. Documentation, formatting,
installer, runtime-policy and build-context checks pass. The candidate image and
root evidence pass the maintained vulnerability policy; no gate was waived.

Fresh live checks:

- GPT-6 Luna, two Runs on different Workers, with retained image input and two
  successful Bash calls per Run. Both image recalls pass. The second Run's first
  upstream input is 24,104 B rather than its 3,115,603 B full internal request.
  Actual provider Pod transmission is 2,468,819 B for the first three-request Run
  and 79,625 B for the second; these counters include responses and incidental
  traffic, not just the selected upstream JSON body.
- DeepSeek Flash: text, write/Bash, high-thinking follow-up and attached-image
  cases all pass. Search was not tested.
- Native input/recovery: consume, Stop, Worker loss, streaming Stop and combined
  Worker/Control Plane loss all pass. The accepted Run/input and interrupted native
  text remain recoverable; streaming bodies do not accumulate in PostgreSQL.
- One synthetic, unreferenced `gpt-image-2` Images request through the existing
  image client returned a valid 981,165 B PNG in 12,782 ms. It was sent once;
  no user image or conversation was used. A separate single edit request with a
  synthetic 512-pixel reference returned a valid 1,163,310 B PNG in 15,869 ms.
  These verify generation/reference-edit transport, not every visual style.

Owned Luna, Flash and recovery resources were physically reconciled and purged.
The final preservation check retains both original machine allocations, all 32
account and 35 model-profile records, and both original credential-file hashes;
all 26 serving Pods are ready.
Private evidence is kept under the runtime `work-evidence/provider-v8-20261106`
directory; user data, credentials and conversation bodies are not published here.

## Failed checks and limits

The first publication preparation rejected two pre-existing acceptance-only script
differences against the installed baseline. Their changes were reviewed, classified
as operator code and covered by fixture checks; runtime admission was not bypassed.

The first live continuation run passed image recall, Tools and protocol/delta checks
but failed an obsolete cold-upload lower bound based on base64-expanded JSON.
v8 enables upstream WebSocket write compression; the prior pin disabled it. The
driver now compares the cold wire floor with the already compressed, high-entropy
PNG size and retains the same upper bounds against repeated historical images.
Local counter examples and upstream compression round-trip/RSV1 race tests pass.
Driver `0f92a20b` records measurements before assertions; its unchanged runtime
repeat passed both distinct-Worker rounds. The failed first sample is retained.

An initial readiness summary counted the previous day's successful database
bootstrap Job as unready. The clarification excludes completed Jobs: 26 serving
Pods were ready. An exec probe also raced the intentionally killed Control Plane
container during recovery; the driver verified the kill/restart and final recovery.

The approximately 131 MiB cold-upload probe remains owner-deferred. Single-host
acceptance does not establish multi-node availability or complete financial
metering. The upstream asynchronous usage queue is still not a billing ledger.
