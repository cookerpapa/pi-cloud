# 云端开发机重新绑定验收

日期：2026-09-30。决定：[ADR-0202](../adr/0202-development-machine-workspace-rebinding.md)。
运行版本：`8674e29bc1d855300a79e709abec6804eb28a504`。

原恢复弹窗只列弹性 Workspace，后端也把绑定强制设成弹性 `/workspace`。
现在缺失 Workspace 的会话可以选择已有弹性 Workspace、新建弹性 Workspace，
或者自己的云端开发机及目录。开发机无需重建；已暂停的机器可通过已有资源 API
恢复。选择器独立管理恢复过程中的状态，打开时刷新列表，并复用目录浏览能力。

后端根据 Workspace 类型选择执行模式，在同一事务中更新项目、Workspace、
开发机、规格和目录。开发机必须属于当前用户及会话创建者；原生 Session 身份、
模型设置、历史和已接受 Run 的环境快照保留。仍仅允许恢复已删除的 Workspace，
且要求会话和物理 Session 执行已经结束。机器锁先于 Workspace 锁；拿锁后用新
快照检查释放意图，避免把会话绑定到即将被释放的机器。

请求重试复用目标和幂等键。新建 Workspace 已成功、绑定响应丢失时，不会因重试
再次创建 Workspace。下次执行通过既有 `workspace_changed` 事实告知模型更换
工作环境，提示使用当前目录，不再写死 `/workspace`，也不假设开发机的文件为空。
不迁移原 Workspace 的文件或进程。

[验收记录](workspace-rebind-live-20260930.json)包括：

- **305 项相关测试通过**：真实 PG 绑定/开发机 23 项、注册与会话 9 项、协议
  99 项、Web 146 项、World State 5 项、Runner 集成 23 项。
- 两项绑定/释放竞态及幂等快照用例加入故障门禁，并单独用真实 PG 验证通过。
  本切片没有重新执行全部故障矩阵。期间修正了测试使用旧取消入口及错误状态名称
  的问题，生产代码没有加入兼容分支。
- 实际 Chrome 验证没有弹性 Workspace 时仍能选择开发机、恢复暂停机器、选择
  目录，以及绑定响应丢失后的重试。类型检查、Web 构建、格式、文档及镜像检查通过。
- 真实 GPT-6 Luna 第一轮在原会话记住随机标记；删除其弹性 Workspace 后，在
  浏览器中选择测试开发机的 `/home/user/rebind-proof`。第二轮成功回忆标记，
  Bash 返回该目录，write 写入的文件可通过会话文件 API 读取。
- 绑定前后原历史前缀摘要一致，模型设置一致，下一轮仅产生一条 Workspace
  变更事实。两轮 Run 均完成，第二轮的 Bash/write 均成功。

API、Worker、Web 已配套部署；无数据库迁移，Guest 构建身份未变。
原有 1,534 条原生日志在部署前后及验收后校验一致（验收后排除本次临时租户）。
