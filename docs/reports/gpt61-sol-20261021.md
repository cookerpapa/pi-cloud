## Fast routing finding

The real request carrying `service_tier: fast` was accepted but reported
`service_tier: default`. Inspection of the pinned CLIProxyAPI translator shows
that it drops tiers other than `priority`. The inspected Codex source also maps
the product name Fast to `priority`. However, a separate real `priority` request
still reported `default`; correcting the spelling alone has not established
effective accelerated routing for this deployment.

The existing Fast setting is retained; no new mapping or proxy compatibility
patch is inferred from that ambiguous result. Standard-mode acceptance above
does not certify Fast activation, acceleration or premium billing. Follow up
by tracing the exact native outbound request and provider reply/account support,
then fix the existing adapter and require actual tier evidence. See
[the maintained backlog](../BACKLOG.md#effective-fast-routing).
